# 질의회신·판례 정리

raw/에 넣어 둔 자료를 읽고 정리표 하나를 만든다. 자료를 찾는 검색은 사용자가 이미 했다. 사이트를 검색하지 않는다.

## 지켜야 할 것

- raw/의 파일은 읽기만 한다. 수정·이동·삭제·이름 바꾸기를 하지 않는다.
- 쓰기는 out/질의회신_판례_정리표.md 하나에만 한다.
- 웹 접속, 외부 전송, 설치, 서버 실행, 외부 계정 연동을 하지 않는다.
- 원문에 없는 내용을 추측해서 적지 않는다. 판단이나 법적 의견을 덧붙이지 않는다.

## 처리 순서

1. raw/ 아래의 파일 목록을 읽는다. 파일을 두 묶음으로 나눈다.
   - 우리 건 사실관계: 파일 이름이 "우리건"으로 시작하거나 raw/우리건/ 폴더 안에 있는 파일
   - 질의회신·판례 자료: 그 밖의 파일
   - 어느 쪽인지 알 수 없는 파일이 있으면 정리를 시작하기 전에 사용자에게 어느 쪽인지 묻는다.
2. 각 파일의 글을 읽는다. 지원하는 형식은 .txt, .md, 글자가 선택되는 PDF, .docx, .hwpx, .hwp이다.
   - 글을 읽지 못한 파일(글자가 선택되지 않는 PDF, 읽히지 않는 .hwp 등)은 건너뛴다. 파일 이름과 이유를 "읽지 못한 파일" 목록에 적는다.
   - .hwp를 읽지 못하면 .hwpx, .docx, PDF로 저장해서 다시 넣어 달라고 안내한다.
3. 질의회신·판례 자료마다 정리표의 한 줄을 만든다. 항목은 다섯 개다.
   - 출처: 기관, 날짜, 사건번호나 회신 번호, 제목
   - 사실관계 요약: 어떤 설계변경이었는지
   - 쟁점과 결론: 무엇이 쟁점이었고 어떻게 판단했는지
   - 우리 건과 같은 점·다른 점: 우리 건 사실관계와 견주어 같은 점과 다른 점을 나누어 적는다. 우리 건 자료가 여러 개면 우리 건 파일 이름별로 나누어 적는다. 우리 건 자료가 없으면 "〔확인 필요〕 우리 건 자료 없음"이라고 적는다.
   - 원문 핵심 문장: 결론이나 판단이 드러난 문장을 원문 그대로 옮긴다. 고치거나 줄이지 않는다.
4. 원문에서 항목의 내용을 찾지 못하면 그 칸에 〔원문에 없음〕이라고 적는다. 추측해서 채우지 않는다.
5. 표 아래에 두 개의 목록을 만든다.
   - 〔원문에 없음〕 항목: 어느 자료의 어느 항목인지
   - 읽지 못한 파일: 파일 이름과 이유
6. out/질의회신_판례_정리표.md에 저장한다. 이미 같은 이름의 파일이 있으면 덮어쓰기 전에 사용자에게 확인한다.

## 정리표 형식

```
# 질의회신·판례 정리표

| 출처 | 사실관계 요약 | 쟁점과 결론 | 우리 건과 같은 점·다른 점 | 원문 핵심 문장 |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

## 〔원문에 없음〕 항목
- (자료 이름) — (항목)

## 읽지 못한 파일
- (파일 이름) — (이유)
```

- 건마다 한 줄이다. 칸 안의 줄바꿈은 `<br>`로 쓰고, `|` 글자는 `\|`로 쓴다.
- 해당하는 항목이 없으면 목록에는 "없음"이라고 적는다.

## 끝낸 뒤 사용자에게 알릴 것

- 정리한 자료의 개수와 읽지 못한 파일의 개수
- 〔원문에 없음〕이 적힌 항목의 개수
- 저장한 파일 경로
